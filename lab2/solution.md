# ДЗ 2. Hadoop экосистема и MapReduce

## Формулировка задания

**Цель**: освоить модель MapReduce и её ограничения.

**Задание**: реализовать задачу подсчёта TF-IDF или топ-N слов по корпусу текстов с использованием Hadoop MapReduce.
Объяснить, как происходит shuffle и sort. Сравнить с локальной реализацией.

**Форма отчетности**: в отчёте должно содержаться описание используемых данных и решаемой задачи, а также реализованного
MapReduce-решения. Необходимо описать работу Mapper и Reducer, привести промежуточные пары (key, value) и объяснить роль
этапа Shuffle/Sort в решении задачи. Также необходимо описать запуск MapReduce-задачи, привести пример полученного
результата и сравнить его с результатом и временем выполнения локальной реализации.

**Критерии (max 6 б.)**: корректная реализация алгоритма TF-IDF или топ-N слов на Hadoop MapReduce, верные результаты
работы
кода, подробное объяснение этапов shuffle и sort, обоснованное сравнение с локальной реализацией, отчет содержит
корректное описание механизмов обеспечения надежности и масштабируемости HDFS.

**Выбранная задача**: `Top-K слов по корпусу текстов`

## Архитектура решения

1. Загружаем набор текстов с HDFS, используем `TextInputFormat`. В mapper попадает (offset, line).
2. Токенизируем текст в `TokenizeMapper` - слова приводятся к нижнему регистру, цифры знаки препинания и прочее
   выкидываются. Маппер не выполняет подсчетов и выдает (word, 1).
3. Считает локальную сумму по словам в `SumCombiner` (== `SumReducer`). На выход (word, partialSum).
4. Shuffle and sort. Сортировка на этом этапе крайне важна, тк она гарантирует, что все вхождения ключа попадут на 1
   mapper, без этого 2 map-reduce job'а не будет работать корректно.
5. Считаем глобальную сумму по словам, на данном этапе у нас набор файлов с бинарных файлов содержащий KV <word, sum>
6. Сбрасываем на диск и запускаем вторую джобу
7. Вычитываем данные в формате для KV `SequenceFileInputFormat` - специальный формат бинарных данных hadoop.
8. Маппер в памяти держит top-k при помощи heap, при завершении сбрасывает кучу в output. Исходим из того, что K не
   огромно и помещается в памяти одного маппера. На выходе получаем <= K наиболее часто встречающихся слов попавших на
   этот маппер. Из-за сортировки в прошлой джобе слово попадает максимум в 1 маппер. Используется композитный ключ
   `CountWordKey` для того, чтобы делегировать глобальную сортировку hadoop.
9. Shuffle and sort. Сортирует все heap'ы, на выходе нам остается только взять top-k из них.
10. `TopKReducer` Берет первые K значений, тк сортировка уже готова. Число reducer'ов = 1, для того, чтобы получить
    финальный результат.

## Используемые данные

Для анализа используется 10 книг на английском языке, размер файлов небольшой, но нам хватит.

Названия и размер книг [books.csv](books.csv).

```shell
chmod +x download_books.sh
./download_books.sh
```

Загружаем данные в hdfs

```shell
docker exec -it namenode sh
hdfs dfs -put /opt/input /input/books
hdfs dfs -ls /input/books
```

## Токенизация

Токенизация реализована в `Tokenizer.java`.
Словом считается любая комбинация удовлетворяющая regex'у `"[A-Za-z]+(?:'[A-Za-z]+)*"`.
Опционально можно включить модель standfordNLP для дедупликации слов, например в базовом варианте whale и whales это два
разных слова, при использовании модели whales будет нормализовано до whale.

## Запуск Job'ы

Собираем fat jar (вместе с моделью StanfordNLP), копируем его в контейнер с клиентом yarn и запускаем:

```shell
cd jobs
./gradlew jar
docker cp build/libs/topk-jobs.jar resourcemanager:/tmp/topk-jobs.jar
docker exec -it resourcemanager yarn jar /tmp/topk-jobs.jar /input/books /output/topk 10 2
```

Формат вызова:

```
yarn jar topk-jobs.jar [-D prop=value] input output [k] [reducers] [useCombiner] [cleanTmp]
```

| Параметр      | По умолчанию | Описание                                                                                                                 |
|---------------|--------------|--------------------------------------------------------------------------------------------------------------------------|
| `input`       | —            | Директория с текстами в HDFS, например `/input/books`                                                                    |
| `output`      | —            | Директория для результата в HDFS. Не должна существовать, иначе job упадет                                               |
| `k`           | `10`         | Сколько самых частых слов вывести                                                                                        |
| `reducers`    | `1`          | Число reducer'ов в job 1 (word count). В job 2 reducer всегда один, иначе не получить глобальный top-K                  |
| `useCombiner` | `true`       | Включить `SumReducer` как combiner в job 1. С `false` удобно сравнивать объем shuffle                                    |
| `cleanTmp`    | `true`       | Удалить промежуточный результат job 1 (`/tmp/topk-wordcount-<uuid>`, путь печатается в лог). `false` - оставить для отладки |

Параметры позиционные: чтобы задать, например, `useCombiner`, нужно указать и все параметры перед ним.
Булевы значения разбираются через `Boolean.parseBoolean`, поэтому любое значение кроме `true` считается `false`.

Через `-D` (до позиционных аргументов) передаются свойства Hadoop и настройки job:

| Свойство          | По умолчанию | Описание                                                                    |
|-------------------|--------------|-----------------------------------------------------------------------------|
| `topk.lemmatize`  | `true`       | Лемматизация через StanfordNLP (`whales` -> `whale`). `false` - только regex |

`k` задается только позиционным аргументом: `-D topk.k=...` перезаписывается значением `k`.

Примеры:

```shell
# top-20 без лемматизации и без combiner'а, 3 reducer'а в job 1
docker exec -it resourcemanager yarn jar /tmp/topk-jobs.jar -D topk.lemmatize=false /input/books /output/topk 20 3 false

# перед повторным запуском удаляем старый результат
docker exec namenode hdfs dfs -rm -r /output/topk
```

Результат:

```shell
docker exec namenode hdfs dfs -cat /output/topk/part-r-00000
```

Прогресс и счетчики (shuffle bytes, spilled records, время) - в YARN UI http://localhost:8088.
